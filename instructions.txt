# Product Clustering Action Plan

## 1. Objective
- Group ~10,000 SKUs into clusters of 5-20 similar products
- Achieve ~80% precision on spot-check sample
- Deliver working code runnable on laptop (16GB RAM)
- Output format: clusters.json mapping cluster_id → [sku_ids...]

## 2. Implementation Plan

### 2.1 Data Preparation [Done]
- Leverage existing data processing pipeline from src/data_processing.py
- Update preprocessing to focus on product similarity rather than USDA mapping:
  - Implemented text normalization (lowercase, strip punctuation, standardize whitespace)
  - Simplified the approach by focusing directly on product descriptions
  - Removed attribute extraction to improve clustering quality
- Created data preprocessing pipeline that directly processes raw product descriptions

### 2.2 Feature Engineering [Done]
- Utilize existing embedding infrastructure (src/VectorDB/localEmbedder.py)
- Continue using the 'all-mpnet-base-v2' model from sentence-transformers
- Create a weighted feature vector combining:
  - Text embeddings from product descriptions (primary feature)
  - Brand information (if available)
  - Size/quantity features
  - Price range indicators (if available)
- Save embeddings to numpy array for reproducibility

### 2.3 Clustering Implementation [Done]
- Created a new clustering.py module
- Implemented HDBSCAN clustering with initial parameters:
  - min_cluster_size=5
  - min_samples=3
  - metric='euclidean'
- Enhanced with improved_clustering.py module for optimized parameters:
  - min_cluster_size=3 (for more granular clusters)
  - min_samples=2 (for more focused product groupings)
  - Added test mode capability for rapid parameter tuning
- Created flexible clustering configurations in max_inclusion_config.json:
  - Granular clusters: min_cluster_size=3, min_samples=2 (default)
  - Balanced clusters: min_cluster_size=6, min_samples=2, epsilon=1.0, alpha=0.4
  - Maximum inclusion: min_cluster_size=10, min_samples=1, epsilon=1.5, alpha=0.5
- Implemented helper functions to analyze cluster statistics

### 2.4 Outlier Handling [Done]
- Identified unclustered products (assigned to noise cluster -1 by HDBSCAN)
- Exported these to a separate file (unclustered.csv) for manual review
- Implemented optimized clustering parameters to achieve better balance between precision and recall
- Added capability to run clustering on subsets of data for faster experimentation embeddings for future re-clustering

### 2.5 Evaluation [Done]
- Created an evaluation module to assess cluster quality
- Implemented metrics including:
  - Cluster coherence (intra-cluster similarity using cosine similarity)
  - Cluster size distribution analysis
  - Automated quality assessment with configurable thresholds
  - Manual review capability through sample cluster display
- Established target precision of 80% with automated verification
- Optimized clustering parameters to improve quality metrics

### 2.6 Export & Visualization [Done]
- Export clusters.json with mapping of cluster_id → [sku_ids...]
- Generate cluster_size_hist.png for distribution visualization
- Create a simple HTML visualization of largest clusters

### 2.7 Domain-Specific Terminology Handling [Done]
- Enhanced abbreviation_translator.py with comprehensive meat industry abbreviations
- Added multi-stage pattern recognition for standardizing meat terminology
- Implemented specialized handling for:
  - Cut variations (ribeye, rib-eye, rib eye)
  - Preparation terms (lip-on, tip-on)
  - Grade indicators (ch, choice, select, prime)
  - USDA code standardization (116A 3, 120 1, etc.)
  - Regional/source indicators (nebraska, omaha, angus)
- Standardized potentially conflicting terms to improve embedding similarity

## 5. Hierarchical Multi-Level Clustering Implementation Plan

### 5.1 Overview
Implement a progressive, hierarchical clustering approach that groups products at multiple levels of granularity, starting with broad categories (e.g., meat, fish, vegetables) and progressively refining to more specific groups (e.g., beef → ground beef → frozen ground beef).

### 5.2 Implementation Steps

#### Phase 1: Core Architecture [Week 1]

1. **Create Hierarchical Configuration Structure**
   - Develop a JSON configuration format for defining multiple clustering levels
   - For each level, specify clustering parameters (min_cluster_size, min_samples, epsilon, etc.) in a seperate config file that can be easily maniupualted
   - Define progression rules between levels
   ```json
   {
     "levels": [
       {
         "level": 1,
         "name": "broad_categories",
         "min_cluster_size": 50,
         "min_samples": 1,
         "epsilon": 1.5,
         "alpha": 0.5
       },
       {
         "level": 2,
         "name": "product_types",
         "min_cluster_size": 20,
         "min_samples": 2,
         "epsilon": 1.0,
         "alpha": 0.4
       },
       {
         "level": 3,
         "name": "specific_products",
         "min_cluster_size": 6,
         "min_samples": 2,
         "epsilon": 0.5,
         "alpha": 0.35
       },
       {
         "level": 4,
         "name": "variants",
         "min_cluster_size": 3,
         "min_samples": 2,
         "epsilon": 0.25,
         "alpha": 0.3
       }
     ]
   }
   ```

2. **Modify improved_clustering.py to Support Multi-Level Processing**
   - Extend the existing HDBSCAN implementation to process clusters at each level
   - Create a new run_hierarchical_clustering function that takes the configuration as input
   - Reuse the existing clustering code with parameterization for each level

3. **Design Cluster Storage Structure**
   - Create a hierarchical JSON format to store multi-level clusters
   - Implement parent-child relationships between clusters at different levels
   ```json
   {
     "level_1": {
       "cluster_1": {
         "name": "Meat",
         "products": [...],
         "children": ["level_2_cluster_1", "level_2_cluster_2"]
       }
     },
     "level_2": {
       "cluster_1": {
         "name": "Beef",
         "parent": "level_1_cluster_1",
         "products": [...],
         "children": ["level_3_cluster_1"]
       }
     }
   }
   ```

#### Phase 2: Clustering Implementation [Week 2]

4. **Implement Level 1 Clustering (Broad Categories)**
   - Use the maximum inclusion configuration (min_cluster_size=50, min_samples=1, epsilon=1.5)
   - Target highest-level categories (meat, fish, produce, etc.)
   - Utilize the all-mpnet-base-v2 embedding model for optimal semantic understanding
   - Store results in the hierarchical format

5. **Implement Sub-Clustering for Each Level 1 Cluster**
   - For each level 1 cluster, extract its products
   - Apply level 2 clustering parameters to create subclusters
   - Maintain parent-child relationships in the output structure
   - Example: Meat → Beef, Pork, Poultry, etc.

6. **Create Progressive Refinement Logic**
   - Build a function to recursively process each level
   ```python
   def cluster_at_level(products, level_config, parent_id=None):
       # Apply clustering using the level-specific parameters
       clusters = run_improved_clustering(
           products, 
           min_cluster_size=level_config['min_cluster_size'],
           min_samples=level_config['min_samples'],
           epsilon=level_config['epsilon'],
           alpha=level_config['alpha']
       )
       
       # Store clusters with parent reference
       cluster_data = {
           f"{level_config['name']}_{i}": {
               "parent": parent_id,
               "products": cluster_products,
               "children": []
           } for i, cluster_products in enumerate(clusters)
       }
       
       return cluster_data
   ```

7. **Implement Stopping Criteria**
   - Define rules for when to stop sub-clustering (min cluster size, max depth)
   - Handle edge cases where clusters can't be further divided

#### Phase 3: Analysis and Visualization [Week 3]

8. **Create Multi-Level Cluster Analysis Tools**
   - Extend current analysis tools to evaluate hierarchical clusters
   - Measure coherence at each level
   - Calculate coverage statistics across the hierarchy

9. **Implement Hierarchical Visualization**
   - Create tools to visualize the cluster hierarchy (tree structure)
   - Enable drill-down from broader to more specific categories
   - Example output format: interactive HTML with expandable tree nodes

10. **Add USDA Mapping Analysis for Hierarchical Clusters**
    - Extend existing USDA analysis to evaluate alignment at each level
    - Determine at which level USDA codes are most consistently grouped
    - Generate reports on hierarchical USDA alignment

#### Phase 4: Integration and Optimization [Week 4]

11. **Integrate with Existing Pipelines**
    - Modify run_clustering.py to support hierarchical mode
    - Add command-line parameters for hierarchical clustering
    - Create a unified interface for both flat and hierarchical clustering

12. **Performance Optimization**
    - Implement caching for embeddings to avoid recalculation
    - Add parallel processing for sub-clustering operations
    - Optimize memory usage for large product sets

13. **Documentation and Examples**
    - Update README with hierarchical clustering documentation
    - Create example notebooks showing hierarchical analysis
    - Document configuration options for different use cases
